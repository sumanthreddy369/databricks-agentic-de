# A2: Producer schema drift

Problem ID: A2. Layer A: Ingestion - Kafka/Redpanda stream and Autoloader roster feed.

## What happens

A field is added, renamed, or retyped upstream. Additive changes are usually safe; breaking ones silently null columns.

## Who it affects

Data engineers.

## How to detect it

Diff observed payload schema vs common/contracts.py; rising _corrupt_record or NULL rate on a column.

## What to do

Classify additive vs breaking. Additive: report and open a contract-change ticket. Breaking: escalate with the diff, never auto-fix.

## Autonomy

Level L1 (L1: recommend and escalate to a person; the agent changes nothing).

## Status in this project

Partly built. detect_schema_drift works on local state only; no live source
