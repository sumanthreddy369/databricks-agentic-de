# N2: Schema or logic change breaks a streaming checkpoint

Problem ID: N2. Layer N: Getting changes to production on Databricks - bundles, deploys, migrations.

## What happens

Changing a streaming table's schema or stateful logic (watermark, dedup keys, aggregation) makes the next update fail on incompatible state or schema.

## Who it affects

Data engineers.

## How to detect it

Update fails right after a deploy with a state/schema incompatibility error on one table.

## What to do

Name the table and the deploy that changed it; prepare a full-refresh plan for just that table and get human approval. Never full-refresh autonomously.

## Autonomy

Level L1 (L1: recommend and escalate to a person; the agent changes nothing).

## Status in this project

Not built yet - handle by hand.
