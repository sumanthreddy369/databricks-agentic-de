# J4: Oversized messages

Problem ID: J4. Layer J: Data overload - volume, bursts, skew.

## What happens

Huge notes or embedded attachments exceed the broker message limit or blow up memory.

## Who it affects

Data engineers.

## How to detect it

Message size distribution; producer errors for too-large records.

## What to do

Escalate to the producer team with sizes. (Today MAX_NOTES_LENGTH only caps the injection scan.)

## Autonomy

Level L1 (L1: recommend and escalate to a person; the agent changes nothing).

## Status in this project

Not built yet - handle by hand.
