# J3: Partition skew / hot key

Problem ID: J3. Layer J: Data overload - volume, bursts, skew.

## What happens

One Kafka partition or one key carries most traffic; a few tasks run for minutes while the rest idle.

## Who it affects

Data engineers.

## How to detect it

Per-partition offsets and task duration spread.

## What to do

Report the hot key/partition; recommend repartitioning or a producer key change.

## Autonomy

Level L1 (L1: recommend and escalate to a person; the agent changes nothing).

## Status in this project

Not built yet - handle by hand.
