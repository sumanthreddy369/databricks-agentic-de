# N4: Untested pipeline changes reach production

Problem ID: N4. Layer N: Getting changes to production on Databricks - bundles, deploys, migrations.

## What happens

SQL or DLT logic changes merge without data tests, so problems surface on live data.

## Who it affects

Data engineers.

## How to detect it

Pull request changes pipeline/ or Gold SQL without matching test changes.

## What to do

Run the dataset-graph test and scenario evals on the change; block the merge if they fail.

## Autonomy

Level L1 (L1: recommend and escalate to a person; the agent changes nothing).

## Status in this project

Partly built. CI runs tests and the DLT dataset-graph test; no data tests on real samples
